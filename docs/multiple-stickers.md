# 한 사진 여러 스티커 수정 계획

단계 A의 단일 배치 상태를 단계 B에서도 유지해 라이브러리 클릭이 기존 스티커를 교체했다. 같은 파일의 반복 배치와 다른 파일의 추가 배치 모두 지원해야 하는 사용 흐름을 빠뜨렸다.

변경: asset ID(라이브러리 파일)와 instance ID(각 배치)를 분리하고 인스턴스 배열로 관리한다. 클릭마다 추가, 개별 선택·변환, 선택 복제/삭제/앞뒤 순서, 단일 사진 undo/redo, 전체 인스턴스 합성 저장을 구현한다. 다중 사진·저장하고 다음·프로젝트 자동 저장은 추가하지 않는다.

검증: 순수 상태 테스트 및 같은 스티커 2개+다른 스티커 추가의 실패 재현 → 구현 → 실제 Electron에서 개별 상태/겹침/픽셀/삭제·undo/참조 보호/저장 실패 유지 → 기존 전체 회귀. 로컬 검증 후 커밋·푸시하고 Windows 재검증 명령을 제공한다.

## 변경 결과

- 라이브러리 asset ID와 각 배치의 UUID를 구분한다. 라이브러리 클릭/PNG 열기마다 인스턴스를 추가하고 새 인스턴스를 선택한다. 기존 인스턴스의 위치·크기·회전은 유지한다. 새 항목은 가운데 근처에 20px씩 어긋나게 추가해 반복 클릭이 보이도록 한다(10개 주기, 작은 사진은 오프셋 축소). 겹친 항목은 사진에서 이동하거나 배치 목록으로 선택할 수 있다.
- 사진 클릭 또는 배치 목록에서 개별 선택한다. 선택 복제는 같은 이미지와 변환을 유지하고 중심을 20px 옮긴 별도 ID를 만든다. 삭제는 선택한 인스턴스만, 앞/뒤는 한 단계씩 바꾸며 저장도 같은 z-order 순서로 합성한다.
- 사진 한 장의 undo/redo 50단계를 추가했다. 드래그/회전/핸들 크기 조절은 종료 이벤트에서 한 작업으로 기록한다. 선택은 편집 이력·수정 상태를 바꾸지 않는다. 숫자 입력은 유효한 입력 변경마다 기록한다. 저장 후 편집/undo/redo는 다시 수정 상태가 된다(저장 시점과 동일해도 보수적으로 수정 상태).
- 최대 200개 인스턴스와 서로 다른 이미지 총 32,000,000 디코드 픽셀(약 128 MiB RGBA)을 제한으로 둔다. 같은 스티커는 IPC 재읽기·디코드를 반복하지 않고 하나의 bitmap을 공유한다. 현재/과거/미래 이력 어디에서도 참조하지 않는 bitmap은 close한다. 앱 종료 때도 전부 해제한다.
- 현재 배치와 undo/redo 이력에서 참조 중인 모든 asset ID를 main에 동기화한다. main은 현재 사진 ID/허용한 asset ID 집합/중복/항목 수/타입/sender/frame/URL을 검사한다. 마지막으로 클릭한 스티커만 보호하던 로직을 수정했다. 해당 파일의 라이브러리 삭제는 참조가 끝날 때까지 차단한다.
- `배치·이력 비우기`는 확인 창에서 동의해야 현재 배치와 이력 전부를 지운다. 취소하면 유지한다. 이 작업은 실행 취소할 수 없다. 완료하면 bitmap/라이브러리 참조를 해제한다. 사진과 PNG 원본, 저장 결과 및 라이브러리 항목 자체는 삭제하지 않는다.
- Canvas 사진 레이어와 선택 UI 레이어 분리를 유지한다. 결과는 별도 원본 크기 Canvas에서 모든 인스턴스를 합성한다. 기존 저장 취소/실패/종료 경고는 전체 배열과 선택을 유지한다.

## 실제 검증

환경: macOS 26.3 arm64, npm 스크립트 Node 24.22.2 / Electron 45.2.1.

- `npm test`: 39개 통과(기존 35 + 상태 모델 4). 인스턴스 독립성·ID 충돌·복제/삭제/순서·undo/redo 분기·200개 및 50단계 상한·잘못된 변환을 검사했다.
- `npm run test:e2e`: 기존 13개 + 혼합 다중 배치 1개 = 14개 통과. 마지막 보완 후 해당 다중 배치 테스트도 재실행해 통과했다.
- `npm run typecheck`, `npm run lint`, Electron 빌드 통과. 공백/개인 경로/비밀값 점검 후 커밋·푸시한다.
- 신규 E2E: 같은 asset 두 번 + 다른 asset → 첫 배치 변환 보존, 다른 배치 선택 중에도 원래 asset 삭제 차단, PNG의 회전된 빨강/초록과 겹침 픽셀, 앞/뒤 변경 전후 프리뷰·PNG 일치, 삭제/undo/redo/복제, 사진 클릭 선택, 4개 배치에서 저장 실패·종료 취소 후 유지와 재저장, 같은 asset 재사용/undo/복제 시 추가 디코드 없음, 비우기 취소/확인 및 main 참조 해제를 검증했다.
- 기존 단일 스티커 변환·투명도·잘림·원본 SHA-256·보안 IPC·EXIF·라이브러리/ZIP·종료·화면 배율 1/2 테스트도 유지했다. 추가 의존성은 없다.

## 남은 범위

이번 변경은 단일 사진의 여러 스티커 편집이다. 단계 C의 다중 사진·사진별 이동/저장하고 다음은 구현하지 않았다. 프로젝트 자동 저장/복구도 없다. 라이브러리는 재실행 유지되지만 사진의 배치·이력은 종료하면 사라진다.

Windows에서 새 14개 테스트와 동일/다른 스티커 반복 배치·겹침·저장을 재확인해야 한다. 200개 전부를 GUI로 연속 조작하는 실장비 성능, 디코드 한도에 가까운 대형 asset 혼합의 장시간 메모리는 미검증이다. 기존 라이브러리 manifest/ZIP 형식은 바꾸지 않는다.
