# 단계 C — 여러 사진 반복 편집

범위: 여러 JPG/PNG 선택·추가, 사진 목록·현재 번호, 사진별 배치/선택/undo/저장 상태, 저장하고 다음, 사진 전환의 저장·버리기·취소. 출력은 기존 원본 크기 PNG이며 리사이즈/JPG는 단계 D다.

계획: 사진 접근을 main의 ID 기반 저장소로 분리 → renderer의 세션별 이력과 전환 → 저장/취소/종료 통합 → 회귀 검증. 현재 문서에 있는 Windows 15개 성공과 수동 키보드 확인 기록은 보존한다.

검증: 먼저 사진 저장소의 ID/중복/배치 등록 실패/원본 변경 및 사진별 저장 상태 테스트를 작성해 실패를 확인한다. 실제 Electron에서 서로 다른 사진의 배치·undo 독립성, 전환 취소·버리기·저장 실패, 저장하고 다음·마지막 완료, 비현재 사진 참조 보호, 디코드 실패와 원본 SHA-256을 검사한다. 기존 전체 E2E·unit·typecheck·lint·build·diff 검사를 실행한다. Windows 자동/수동은 사용자 일정에 맞춰 검증 대기로 기록한다.

구현 결정과 실제 결과는 아래에 추가한다.

## 구현 결정

- main `PhotoStore`에 사용자가 대화상자로 선택한 사진만 ID·실제 경로·SHA-256으로 매핑한다. renderer에는 경로를 전달하지 않는다. `choosePhotos`와 `readPhoto(id)`만 노출한다. sender/frame/인자/허용 ID를 검사하고 main 파일 작업은 기존 busy 잠금으로 직렬화한다.
- 세션 최대 100장, 파일당 32 MiB·1,600만 픽셀·한 변 8,192px. 여러 파일은 순차 검증·썸네일 생성 후 모두 유효할 때만 등록한다. 기존 파일을 다시 선택하면 같은 ID를 유지한다. 폴더 일괄 탐색 대신 다중 파일 선택을 제공한다.
- 썸네일은 최대 120×120의 PNG data URL이다. 원본은 현재 사진만 renderer에서 디코드하고 전환 때 새 디코드 성공 후 이전 bitmap을 해제한다. 전환 중 최대 두 장을 유지한다. 원본이 외부에서 변경되면 재읽기 해시 검사로 전환을 거부한다. UI 전환·가져오기·저장 전체를 잠가 뒤늦은 디코드가 다른 사진을 덮지 않도록 한다.
- 사진마다 배치·선택·최대 50단계 undo/redo, 수정 여부, 저장 완료 여부와 마지막 저장 배치(checkpoint)를 보관한다. 선택만 바꾸면 수정 상태가 되지 않는다. 저장 뒤 편집/undo/redo는 보수적으로 다시 수정 상태다.
- 사진 전환 시 수정된 현재 사진은 저장·버리기·취소를 묻는다. 저장 취소/실패는 이동하지 않는다. 버리기는 **대상 사진 디코드 성공 후** 마지막 저장 배치(미저장 사진은 빈 배치)로 되돌리고 현재 사진의 이력을 비운다. 일반 전환은 각 사진의 선택·이력을 유지한다. 따라서 비현재 사진에는 미저장 수정이 남지 않으며 기존 종료 확인도 모든 미저장 편집을 보호한다.
- `저장하고 다음`은 쓰기 성공 뒤 다음 사진을 로드한다. 이미 저장하고 수정하지 않은 사진은 추가 파일 없이 이동한다. 마지막 사진은 완료 안내만 하며 다시 눌러도 순환·중복 저장하지 않는다. 출력 폴더 선택은 저장할 때마다 한다. 저장 중 중복 클릭과 다른 편집을 차단한다.
- 스티커 bitmap은 모든 사진 사이에서 공유한다. 전체 사진의 현재/과거/미래/마지막 저장 배치에서 참조하는 asset을 main에도 사진별로 동기화한다. 비현재 사진의 참조도 삭제를 막는다. 마지막 저장 배치는 버리기 복원을 위해 유지하므로 `배치·이력 비우기` 후에도 참조할 수 있다. 빈 배치를 다시 저장하면 이전 checkpoint 참조도 해제된다. 총 디코드 한도 3,200만 픽셀은 전체 세션에 적용한다.
- 스티커 manifest·ZIP 형식은 바꾸지 않는다. 사진 목록·편집 이력은 메모리 세션이며 재실행 복구는 제공하지 않는다. 확대/축소 UI·리사이즈·JPG 출력·사진 목록 제거/정렬은 이번 범위에 추가하지 않았다.

## 검증과 남은 범위

사진 저장소·상태 모델이 없는 상태에서 신규 unit 테스트 실패를 확인했다. 구현 후 ID/중복/등록 원자성/100장 상한/원본 변경 거부와 사진별 수정·저장·버리기 상태 테스트를 통과했다. 회귀 중 빈 배치 재저장 후 main의 checkpoint 참조가 남는 문제를 재현해 저장 후 참조 동기화로 수정했다.

macOS 26.3 arm64 개발 환경에서 단위/파일 I/O 41개, Electron E2E 17개 전체 통과를 확인했다(최종 E2E 19.6초). E2E는 파일 대화상자 결과만 대체하고 실제 main/preload/renderer·오프라인·Canvas·파일 쓰기를 사용한다. 새 테스트는 가로/세로 두 사진, 서로 다른 배치·사진별 undo/redo, 저장·다음 취소/실패/성공, 마지막 완료·반복 저장 방지, 전환 저장/버리기/취소·대상 파일 누락, 저장 후 수정 표시, 비현재 사진 asset 보호, 출력 픽셀·원본 해시, 전체 사진을 미리 디코드하지 않음·전환 후 사진 bitmap 1개 유지를 확인한다.

Windows는 사용자가 추후 한 번에 테스트할 계획이며 이번 단계 C 자동·수동 결과는 대기다. 100장/사진별 최대 이력과 디코드 한도 근처의 장시간 실장비 메모리, 설치·업그레이드·제거는 미검증이다. 최대 이력은 사진당 50단계×200배치×100장으로 상한이 있으며 대량 작업에서는 상태 배열도 추가 메모리를 사용한다. Windows 누적 확인 항목은 `windows-validation.md`에 기록한다.
