# 동영상: MP4 저장·영상 자르기·소리 옵션·HDR 색 (2026-11-28)

GIF 만들기([gif.md](./gif.md))를 `동영상` 모드로 넓혔다. ffmpeg는 그대로 사용자가 직접 설치한 것만 쓴다(번들·자동 설치 없음, `shell: false`, 고정 인자 배열).

## 흐름
- 툴바 탭 이름을 `GIF 만들기` → `동영상`(좁은 창 `영상`)으로 바꿨다. 오른쪽 패널 `GIF · 움짤 | MP4 · 동영상`에서 저장 형식을 고르고, 고른 형식은 다음 실행에도 기억한다.
- **자르기**: 자르지 않음·자유 비율·16:9·4:3·1:1·3:4·9:16. 미리보기 위 상자를 끌어 옮기고 핸들로 크기를 바꾼다(비율이 있으면 모서리 핸들만). 화면 가장자리에 손이 나온 영상처럼 필요 없는 부분을 빼는 용도다. GIF와 MP4에 모두 적용된다.
- **MP4**: 너비 원본/1920/1280/1080/720/480(원본·자른 영역보다 큰 값은 숨김), `소리 포함` 체크(기본 켬, 기억). 소리가 없는 영상이면 체크를 끄고 `소리 없음`으로 표시한다. 구간은 최대 10분(GIF 30초). 형식을 GIF로 바꾸면 30초가 넘는 구간을 줄인다.
- 결과는 `<원본이름>_kkumi.mp4`, 충돌 시 숫자. 원본·기존 파일을 덮지 않는다.

## 좌표·인자
- 자르기 상자는 **회전이 적용된 화면 픽셀**(ffmpeg가 `-i` 정보로 보여 주는 크기, 세로 아이폰 영상은 세로)로 저장한다. ffmpeg는 사용자 필터 전에 회전을 먼저 적용하므로 같은 좌표계다. 4:2:0 때문에 크기·위치는 짝수로 내림한다.
- main은 옵션 키·정수·범위(16px 이상, 영상 안)를 다시 검사한다(`validCropShape`, `cropFits`, `validMp4Options`).
- MP4: `-map 0:v:0`, 소리 유지 `-map 0:a:0? -c:a aac -b:a 160k` / 제거 `-an`, `crop → scale(lanczos) → [HDR 변환] → BT.709 yuv420p`, `-map_metadata -1 -map_chapters -1`(위치·기기 정보 제거), BT.709 표기, `-movflags +faststart`.
- H.264 인코더는 `ffmpeg -encoders`에서 `libx264`(CRF 20) → `h264_mf`(Windows) → `h264_videotoolbox`(macOS) 순서로 고른다. 시스템 인코더는 화소 수 기준 2~12Mbps. 어느 것도 없으면 정식 빌드 설치를 안내한다.
- 큰 파일이라 메모리로 읽지 않는다. ffmpeg가 출력 폴더 안의 숨은 임시 파일(`.<uuid>.tmp`)에 쓰고, `ftyp` 헤더·크기(4GB 이하)를 확인한 뒤 하드 링크로 이름을 붙인다(`publishUnique`). 링크를 못 쓰는 파일시스템은 `COPYFILE_EXCL` 복사, 실패하면 쓰다 만 복사본과 임시 파일을 지운다. 시간 제한 30분, 취소 가능.

## HDR 색 (사용자 보고: GIF에서 빨간 고기가 갈색으로 바램)
- 원인: 아이폰 기본 HDR(HLG·Dolby Vision 8.4)과 갤럭시 HDR10+(PQ)는 BT.2020 색역·HDR 곡선이다. 변환 없이 SDR(GIF·JPEG·H.264)로 바꾸면 BT.709로 잘못 해석되어 채도가 빠지고 빨강이 갈색이 된다. 합성 HLG 영상에서 `#B4282D` → `#8D3628`로 재현했다. 일반(SDR) 영상과 팔레트 방식(`stats_mode=diff/full`)은 차이가 없었다.
- 해결(`shared/hdr.ts`): `ffmpeg -i`의 영상 줄에서 `arib-std-b67`(HLG)·`smpte2084`(PQ)를 읽고, GIF·MP4·미리보기 모두 HDR→SDR 변환을 넣는다. zscale/tonemap은 libzimg가 필요해 빌드마다 없을 수 있으므로(Homebrew에는 없음) **모든 ffmpeg에 있는 필터만** 쓴다.
  - `lutrgb`: HLG 역 OETF / PQ 역 EOTF(BT.2100)로 선형광.
  - HLG OOTF(1000nit 기준 Y^0.2)는 휘도 채널을 만들어 `blend=multiply`로 곱한다(채널별 감마는 채도를 과장해서 쓰지 않음).
  - `colorchannelmixer`: BT.2020 → BT.709 원색 행렬(선형).
  - 톤 매핑: SDR 흰색 203nit(BT.2408) 기준, 흰색의 75%까지 그대로, 그 위는 부드럽게 흰색으로 접는다. 마지막에 감마 2.4.
- HDR 영상은 패널에 `HDR`과 "일반 화면 색(SDR)으로 바꿔 저장" 안내를 보인다. 1080p 125프레임 변환 1.3초(M 시리즈).

## 검증 (macOS 26.3 arm64, ffmpeg 8.0.1 Homebrew)
- 단위: MP4 옵션 검증(10분·너비·소리·자르기), 인코더 선택, 너비 짝수·업스케일 방지, 인자(소리 유지/제거·자르기·BT.709·메타데이터·faststart·시스템 인코더 비트레이트), HDR 곡선 판별·필터 문자열, GIF 자르기 인자, `publishUnique`(링크·복사 대체·번호·부분 복사 정리).
- 실제 ffmpeg 통합(`tests/video-ffmpeg.test.ts`, ffmpeg 없으면 건너뜀): 8색 막대를 HLG·PQ BT.2020 10-bit로 만들어 변환 후 각 색 오차 6 이내, 변환 없으면 빨강 오차 20 초과(문제 재현), GIF 전체 그래프 색 유지. MP4 자르기 크기·소리 유지/제거·BT.709·위치 메타데이터 제거·`ftyp`.
- E2E: 왼쪽 빨간 띠가 있는 640×480 영상 드롭 → MP4 → 3:4 자르기 상자를 오른쪽 끝으로 끌기(280,0,360,480) → 저장(360×480·AAC·왼쪽 픽셀 파랑) → 소리 끄고 다시 저장(`_1`, 오디오 없음) → 원본 SHA-256 불변·임시 파일 없음. 기존 GIF E2E는 새 탭 이름으로 통과. 최소 창(760×580)에서 패널 스크롤 없음(낮은 창에서는 하단 안내문 숨김).
- 미검증: Windows의 `h264_mf` 경로와 winget Gyan 빌드, 실제 아이폰 HLG·Dolby Vision 영상과 갤럭시 HDR10+ 영상의 색(합성 영상으로만 검증), 4K·10분 영상의 시간과 용량.
