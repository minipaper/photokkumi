# 화면 레이아웃 정리 (2026-11-09)

## 문제
- 우측 패널(`aside`) 전체가 스크롤되는데 그 안의 스티커 그리드·배치 목록도 각자 스크롤 → 이중 스크롤.
- 상단이 제목·부제·배지 / 버튼 줄 / 출력 폴더 줄 / 출력 설정 바의 4줄(약 230px)로 캔버스 공간을 차지. 하단 안내문 2줄도 상시 노출.

## 결정
- 상단은 툴바 1줄: `포토꾸미 | 사진 열기 · 입력 폴더 선택 | 실행 취소 · 다시 실행 | 저장 설정▾ · PNG/JPG로 저장 · 저장하고 다음`.
- 출력 폴더·형식·리사이즈·확대 방지는 `저장 설정` 팝오버로 이동. 설정은 재실행 후에도 유지되므로 상시 노출하지 않고 버튼에 요약(`PNG · 원본 크기`)을 표시. 잘못된 값이면 버튼이 빨간색이 되고 저장 버튼이 비활성화됨. 바깥 클릭·Esc로 닫힘.
- 우측 패널은 스크롤하지 않는 고정 높이 열. 스티커 라이브러리 그리드만 남는 높이를 채우며 스크롤하고, 아래 `배치한 스티커`(목록·복제/삭제/순서·X/Y/너비/회전)는 항상 보임.
- 확대/축소 도구와 파일 정보(이름·크기·출력 크기·수정 상태)는 캔버스 아래 얇은 바로 이동.
- 하단은 `‹ n / N ›` + 썸네일 스트립, 그 아래 한 줄 상태바(상태·오류).
- 기능·IPC·편집 로직 변경 없음. 마크업과 CSS만 재구성. `style.css`는 누적 override를 걷어내고 토큰 기반으로 다시 작성.

## 검증 (macOS 26.3 arm64)
- `npm run typecheck`, `npm run lint`, `npm test`(56), `npm run test:e2e`(23) 통과.
- E2E는 출력 설정 조작 전 `저장 설정` 팝오버를 여는 `settings()` 헬퍼를 사용.
- 회귀 테스트 추가: 최소 창 760×580에서 페이지·우측 패널 스크롤 없음, 스티커 그리드만 스크롤, 툴바 높이 ≤ 52px, 캔버스 높이 > 250px, 선택 스티커 입력칸이 화면 안에 보임.
- Windows 화면(DPI 배율 포함) 수동 확인은 대기.
