# 끌어 놓기로 사진 불러오기·목록에서 제거 (2026-11-09)

## 동작
- 탐색기에서 JPG/PNG 파일 여러 장이나 폴더를 창 어디에든 끌어 놓으면 사진 목록에 **추가**한다(기존 목록·편집 유지, 같은 파일은 중복 추가하지 않음).
- 폴더는 `폴더 열기`와 같은 규칙: 바로 아래 JPG/JPEG/PNG만, 이름순, 하위 폴더·symlink 제외.
- 동영상·기타 형식·symlink·읽을 수 없는 파일은 제외하고 상태줄에 개수와 이름을 안내한다. (동영상은 GIF 만들기 모드에서 처리 예정)
- 대화상자·스티커 관리·작업 중에는 놓기를 받지 않는다.
- 썸네일의 `×`로 목록에서 제거한다. 원본 파일은 건드리지 않는다. 미저장 편집이 있으면 확인 후 제거하고, 현재 사진을 제거하면 다음(없으면 이전) 사진으로 이동한다.
- `입력 폴더 선택`은 보조 기능으로 `폴더 열기`로 이름을 바꿨다.

## 보안 결정
- 렌더러는 경로를 다루지 않는다. preload가 렌더러에서 받은 `File`을 `webUtils.getPathForFile`로 변환해 `photo:drop`에 넘긴다. 실제 OS 파일이 아닌 `File`은 빈 경로가 되어 거부된다.
- main은 기존 sender 검증에 더해 경로 배열(1~200개, 절대 경로, NUL 없음)을 검증하고, `lstat`으로 symlink를 거부하며, 실제 decode 검사·100장 한도는 기존 `PhotoStore.add`를 그대로 쓴다.
- 남는 위험: 손상된 렌더러가 위조한 경로를 `photo:drop`에 보내면 decode 가능한 JPG/PNG를 사진 목록에 넣을 수 있다. 읽기 전용이고 이미지로 검증된 파일만 해당하며, 쓰기 경로에는 영향이 없다.
- `photo:remove`는 앱이 발급한 사진 ID만 받는다. main의 스티커 참조도 함께 정리한다.

## 검증 (macOS 26.3 arm64)
- 단위: 끌어 놓은 파일·폴더 추가, 기존 ID 유지, 동영상·텍스트·symlink·없는 파일 제외, 제거 후 읽기 거부, 잘못된 경로 배열 거부.
- E2E: 실제 파일 기반 `File`로 drop 이벤트를 보내 첫 사진 열기 → 추가(중복 제외·텍스트 제외 안내) → 미저장 사진 제거 취소/확인 → 이웃 사진으로 이동 → 마지막 사진 제거 시 빈 화면 → 다시 놓기. preload API 허용 목록과 위조 `File`·잘못된 ID 거부.
- 실제 Windows 탐색기에서 끌어 놓는 수동 확인은 대기.
