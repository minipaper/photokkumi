# 자르기 (0.1.10)

사진 편집 우측 다섯 번째 탭 `자르기`(단축키 `C`). 사용자 요청(2026-11-14)으로 제안 후 추천안대로 구현했다.

## 결정

- **원본 비파괴**: 사진마다 장면(`Scene.crop`)에 자를 범위 `{x, y, width, height, aspect}`를 원본(EXIF 적용) 정수 픽셀로 저장한다. 스티커·가림·글자 좌표는 원본 그대로라 자르기와 섞이지 않고, 범위를 다시 넓히면 잘린 부분이 돌아온다. 사진 전체를 덮는 범위는 `undefined`(자르지 않음)로 정리한다.
- **편집 흐름**: 탭을 열면 캔버스에 사진 전체와 자를 상자(바깥 어둡게, 3등분선)를 보여 주고 다른 항목은 잠근다. 상자 안쪽을 끌면 이동, 핸들로 크기(고정 비율이면 모서리 4개만), 방향키 1px·Shift 10px 이동. 편집은 초안(`cropDraft`)이며 `완료`/Enter/다른 탭/저장/사진 전환/모드 전환에서 **실행 취소 1단계**로 반영하고, `취소`/Esc는 버린다. `원래대로`는 전체 범위로 되돌린 초안이다. 미반영 초안도 닫기 확인에서 수정으로 본다.
- **프리셋**: 자유 · 원본 · 1:1 · 4:3 · 3:2 · 16:9 · 5:4, `가로/세로`로 3:4 · 2:3 · 9:16 · 4:5. 비율을 고르면 그 비율로 가장 크게 가운데에 잡는다(자유는 상자를 그대로 두고 비율만 푼다). 처음 방향은 사진 방향을 따른다.
- **모든 사진에 이 비율**: 다른 사진을 같은 비율로 가운데 자른다. 저장 설정의 가로/세로 사진 길이처럼 **각 사진의 방향을 따른다**(4:3이면 세로 사진은 3:4). 이미 그 비율로 잘린 사진은 직접 맞춘 위치를 지킨다. 사진마다 실행 취소 가능. 자유·원본에서는 꺼진다.
- **보기**: 자른 뒤 캔버스는 자른 영역만 보여 주고(Konva Group을 `-crop.x/y`로 옮기고 그 범위로 clip), 새 스티커·글자는 그 영역 가운데에 놓는다. 자르기 도구는 상자 핸들이 사진 끝에서 잘리지 않게 사진 둘레에 14px 여백을 둔다.
- **저장**: `composePng`가 `crop`만큼 옮겨 그리고 출력 크기·가로/세로 판단은 자른 크기 기준이다. 저장 IPC에 정수 4개 `crop`을 함께 보내고 main은 사진 범위 안인지 확인한 뒤 자른 크기로 결과 크기를 검증한다.
- 픽셀 직접 입력, 썸네일 모드 자르기는 넣지 않았다(썸네일은 배경 확대·위치가 있음). 90° 회전과 기울기(수평 맞추기)는 아래.

## 검증

- 단위 `tests/crop.test.ts` 9개: 프리셋·방향, 가운데 범위, 정리·비교, 범위 검증, 이동·크기 조절(반대쪽 고정·사진 끝·최소 16px·비율 유지), 정수 맞춤, 저장 요청 `crop` 형식.
- E2E `자르기: …`: C키, 1:1·4:3·세로, 상자 끌기·핸들 크기 조절, Esc 취소, 방향키·Enter 완료, 스티커 좌표 유지, 모든 사진에 비율(세로 사진 3:4), 600×800 저장 픽셀, undo/redo, 저장하고 다음 후 둘째 사진 저장, 원래대로.
- 최소 창(760×580)에서 탭 5개·프리셋 설명이 잘리지 않고 패널이 스크롤하지 않음. Windows 맑은 고딕은 더 넓어 설명을 4글자 안팎으로 줄였다.

# 사진 90° 회전 (2026-11-26)

사용자 요청으로 `자르기` 탭 맨 위에 `↺ 왼쪽`·`↻ 오른쪽` 버튼을 넣었다(휴대폰 갤러리처럼 자르기·회전·기울기를 한 도구로).

## 결정

- **저장 형태**: 장면에 `turn`(시계 방향 90° 횟수 1~3, 없으면 0)을 둔다(`src/shared/turn.ts`). EXIF 방향을 적용한 원본 위에 한 번 더 돌리는 값이며 원본 파일은 그대로다.
- **좌표**: 스티커·글자·블러·도형·자를 범위는 돌린 사진 좌표에 있다. 돌릴 때 함께 옮긴다. 오른쪽: `(x, y) → (H − y, x)`, 각도 +90°. 왼쪽: `(x, y) → (y, W − x)`, 각도 −90°. 각도는 −180~180으로 유지한다. 자를 범위는 가로·세로가 바뀌고 비율 이름도 4:3 ↔ 3:4로 바뀐다(1:1·원본·자유는 그대로). 네 번 돌리면 정확히 제자리.
- **화면·저장**: renderer가 현재 사진만 정수 이동+90° 회전으로 다시 그린 사본(보간 없음)을 만들어 캔버스·블러·저장에 그대로 쓴다. 사본은 사진·회전값이 바뀔 때만 만들고 이전 것은 1초 뒤 해제한다. 저장 IPC에 `turn`을 보내고, main은 1~3 정수인지 검사한 뒤 돌린 크기로 자를 범위·출력 크기를 확인한다.
- **실행 취소**: 회전 1번 = 1단계. 편집 중이던 자르기 초안은 먼저 반영한다(별도 단계).
- **목록 썸네일**: 돌린 사진은 하단 썸네일도 CSS로 돌려 보여 준다.
- **모든 사진에 이 비율**: 다른 사진의 방향은 그 사진의 회전값을 반영해 판단한다.
- 최소 창(760×580)에서 회전 줄이 들어가도 패널이 스크롤하지 않게 패널 간격을 12→10px로 줄이고 안내문을 2줄로 줄였다(`원래대로` 툴팁으로 옮김). macOS에서 25px 여유.

## 검증

- 단위 `tests/turn.test.ts` 6개: 크기 교환·값 검증, 오른쪽/왼쪽 좌표·각도·자를 범위·비율, 왕복·4회 제자리, 각도 범위, 블러·자르기 없음, 저장 요청 `turn` 검증(0·4·소수·문자열·추가 필드 거부).
- E2E `사진 회전: …`: 4:3 자르기 후 오른쪽 회전 → 3:4, 목록 썸네일 회전, 최소 창 패널 스크롤 없음, 스티커 중심·각도, 800×1200 저장 네 귀퉁이·스티커 방향 픽셀, undo 3단계·redo, 왼쪽 회전 후 1200×800 저장, 원본 SHA-256 불변.

# 기울기 (2026-11-26)

사용자 요청으로 회전 줄 아래에 `기울기` 눈금자와 숫자 칸을 넣었다. 범위는 사용자 선택대로 갤러리와 같은 **±45°**, 0.1° 단위.

## 결정

- **방식**: 사진만 기울이고 빈 귀퉁이가 생기지 않을 만큼 확대한다(`coverScale`: 틀을 반대로 돌린 외접 사각형 `(W·cos + H·sin) × (W·sin + H·cos)`이 확대한 사진 안에 들어가는 최소 배율). 틀 크기는 그대로라 스티커·글자·블러·자를 범위 좌표와 저장 크기가 바뀌지 않고, 저장 IPC도 바뀌지 않는다. 15°(4:3)는 약 1.31배, 45°는 약 1.65배 확대된다.
- **저장 형태**: 장면 `straighten`(도, 시계 방향, 0.1° 단위, 0이면 저장 안 함, `src/shared/straighten.ts`). 90° 회전과 독립이며 회전해도 값은 그대로다(2D 회전은 교환 가능).
- **그리기**: 90° 회전 사본과 같은 곳(`renderOriented`)에서 가운데 기준 회전+확대를 고품질 보간으로 한 번에 그린다. 캔버스·보정·블러·저장이 모두 이 사본을 쓰므로 미리보기와 결과가 같다. 4000×3000 사진에서 한 단계 그리기가 두 프레임 안(17~25ms, macOS M 계열)이었다.
- **조작**: 눈금자 끌기(5°마다 눈금, 0°는 긴 눈금), 방향키 0.1°·Shift+방향키 1°, 두 번 클릭 0°, 숫자 직접 입력(범위 밖은 ±45°로). 끌기·방향키는 손을 뗄 때 실행 취소 1단계.
- **자르기 초안 유지**: 기울기를 바꾸면 사진 사본이 새로 만들어지지만, 장면의 자르기 객체가 그대로면 편집 중인 자를 상자를 다시 잡지 않는다(`cropBase`).
- 최소 창 여유를 위해 프리셋 버튼 높이 48→40px, 안내문은 한 줄(`Enter 완료 · Esc 취소 · 방향키로 상자 이동`)로 줄였다. macOS 760×580에서 14px 여유.
- 원근 보정(세로·가로 사다리꼴)은 Konva로 그릴 수 없어 넣지 않았다.

## 검증

- 단위 `tests/straighten.test.ts` 3개: 값 검증·정리(0.1°, ±45°, 0 제거), 확대 배율 공식·대칭, 여러 비율·각도에서 틀 네 귀퉁이가 확대한 사진 안에 있음.
- E2E `기울기: …`: 방향키 0.1°/Shift 1°, 두 번 클릭 0°, 8.25→8.3·60→45 정리, 10° 저장 1200×800에서 300곳 이상 픽셀을 역변환 위치의 원본 색과 비교(경계 4px 제외, 오차 3), 네 귀퉁이 불투명, 스티커는 기울지 않음, undo/redo, 자를 상자 유지, 원본 SHA-256 불변.

# 사진 불러오기 진행 표시 경합 수정 (2026-11-26)

`사진 불러오는 중… 1/2` 진행 메시지는 별도 IPC 채널로 와서 가져오기 결과보다 늦게 도착할 수 있었다. 그러면 `사진 1장 추가` 상태를 덮어 E2E `탐색기에서 끌어 놓은 사진…`이 간헐적으로 실패했다(수정 전 코드에서 6회 중 4회). 가져오기 IPC를 기다리는 동안에만 진행 메시지를 표시하도록 고쳤고, 6회 반복 모두 통과했다.

# 자동 수평 (2026-11-27)

사용자 요청으로 기울기 줄에 `자동` 버튼을 넣었다. 모델·라이브러리 없이 직접 계산한다(`src/shared/level.ts`).

## 결정

- **방식**: 돌린(기울이기 전) 사진을 긴 변 640px로 줄여 → Sobel로 강한 경계만 고르고(최대값의 25%, 최소 60) → 각 점의 선 방향이 후보 각도 ±2° 안이면 선의 법선 방향 거리(1px 칸)에 투표 → 칸 값 제곱합이 가장 큰 각도를 고른다(긴 직선 하나가 흩어진 짧은 조각보다 이김). 0.1° 간격, 포물선 보간 후 0.1°로 반올림. 결과의 반대 각도를 기울기로 넣는다(실행 취소 1단계).
- **범위 ±15°**: 휴대폰 사진은 보통 몇 도 안이고, 넓히면 지붕·계단 같은 대각선을 수평으로 착각한다. 눈금자는 그대로 ±45°.
- **가로선 우선**: 세로선은 0.5배로만 반영한다. 올려다본 건물처럼 원근으로 모인 세로선이 결과를 흔들지 않게.
- **못 찾으면 안내만**: 가장 긴 직선이 짧은 변의 25%에 못 미치면(음식 클로즈업·인물·질감뿐인 사진) 값을 바꾸지 않고 `수평 기준이 될 직선…을 찾지 못했습니다`를 띄운다. 이미 같은 값이면 `이미 자동 수평`.
- **레이아웃**: `기울기 [숫자] [자동]` 줄과 패널 전체 폭 눈금자 줄로 나눴다(최소 창에서도 눈금자가 넓음). 안내문은 없애고 키 설명은 `완료`·눈금자 툴팁으로 옮겨, Windows 글꼴로 줄바꿈될 문장이 패널에 남지 않는다. macOS 760×580에서 12px 여유.

## 검증

- 단위 `tests/level.test.ts` 5개: 0°·±0.7°~14° 수평선 오차 0.2° 이내(잡음 포함), 세로 사진·RGBA·세로 기둥만 있는 사진, 원근으로 모인 기둥 + 3° 수평선 → 3°(오차 0.3), 질감만·원·범위 밖 대각선·너무 작은 사진 → null, 640px 처리 0.5초 이내.
- E2E `자동 수평: …`: 직선 없는 사진은 안내만·값 0·수정 표시 없음, 4° 기울어진 1200×800 수평선 → −4°(오차 0.3), 다시 누르면 `이미 자동 수평`, undo 1번에 0°.
- 실제 사진(건물·바다·실내)에서의 정확도는 합성 이미지로만 확인했다. 사용 중 틀리는 사진이 있으면 그 유형으로 테스트를 추가한다.
