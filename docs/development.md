# 포토꾸미 · PhotoKkumi — 개발 문서

> 앱 소개·설치 안내는 저장소 첫 화면의 [README](../README.md)에 있습니다. 이 문서는 개발 범위·명령·검증 상태를 다룹니다. README 스크린샷은 `npm run build && npm run shots`로 합성 이미지에서 다시 만듭니다(ffmpeg·macOS sips 필요).

> 내 스티커로 꾸미고, 다음 사진으로.

블로그에 올릴 사진을 빠르게 준비하는 **Windows용 로컬 데스크톱 앱**입니다. 사진을 열고, 미리 등록한 투명 PNG 스티커로 얼굴을 가리거나 사진을 꾸민 뒤, 크기를 맞춰 저장하고 다음 사진으로 넘어가는 반복 작업에 집중합니다.

**현재 상태: 폴더 입력·하단 썸네일·블로그 리사이즈·스티커 관리 분리 구현 및 macOS 자동 검증 완료. 화면은 상단 툴바 1줄·`저장 설정` 팝오버·스크롤 없는 우측 패널로 정리했습니다([화면 레이아웃 기록](./ui-layout.md)). 탐색기에서 사진·폴더를 끌어 놓아 추가하고 썸네일 `×`로 목록에서 제거합니다([끌어 놓기 기록](./drop-import.md)). `블러·모자이크`로 사진 위에 타원 가림 영역을 그려 스티커처럼 이동·크기·회전하고 강도를 조절합니다([블러·모자이크 기록](./blur-regions.md)). 우측 `보정` 탭에서 노출·대비·채도·색온도를 조절하고 모든 사진에 같은 값을 적용할 수 있습니다([보정 기록](./adjustments.md)). `GIF 만들기` 모드에서 MOV/MP4의 구간을 `[` `]`로 골라 GIF로 저장합니다. 이 기능은 사용자가 따로 설치한 ffmpeg를 사용하며 앱에 포함하지 않습니다([GIF 기록](./gif.md)). 0.1.4부터 고양이·토끼·양·너구리 7방향 기본 스티커 28장이 `animal` 분류로 한 번 들어갑니다([기본 스티커 기록](./default-stickers.md)).** 입력 폴더 또는 여러 JPG/PNG 사진을 열고 하단 썸네일에서 전환하며 사진별 스티커 배치·선택·undo/redo·저장 상태를 유지합니다. PNG 스티커 라이브러리, 다중 배치·복제·삭제·겹침 순서와 원본/가로 너비·긴 축 기준 JPG·PNG 저장을 제공합니다. 확대 방지와 JPG 품질 100 고정 저장을 지원하며 공통 출력 설정은 재실행 후에도 유지합니다. `저장하고 다음`은 저장 성공 후에만 다음 사진으로 이동하며 마지막 사진에서는 완료를 안내합니다. 사진을 바꾸거나 종료할 때 수정 내용의 저장·버리기·취소를 선택합니다.

선택한 스티커는 **Delete/Backspace로 삭제**, **방향키로 원본 기준 1px 이동**, **Shift+방향키로 10px 이동**합니다. 입력칸에서는 입력을 우선하며 캔버스를 클릭하면 스티커 조작으로 돌아갑니다. 회전 핸들에 마우스를 올리면 원형 화살표 커서가 표시됩니다. 삭제·이동도 실행 취소/다시 실행할 수 있습니다. Ctrl/Cmd+Z로 실행 취소, Ctrl/Cmd+Shift+Z 또는 Ctrl/Cmd+Y로 다시 실행, Ctrl/Cmd+D로 선택 스티커를 복제합니다. 입력칸·관리 화면에서는 편집 단축키를 가로채지 않습니다.

## 현재 앱 실행과 검증

Node **24.22.2 LTS**, npm 사용. `.nvmrc`와 lockfile에 버전을 기록했습니다. npm 스크립트도 개발 의존성으로 고정한 Node 24.22.2를 사용합니다. Electron **45.2.1**, electron-vite **6.0.0**, React **19.3.1**, Konva **10.9.1** / react-konva **19.3.2**, TypeScript strict 구성입니다.

```sh
npm ci
npx install-electron --no
npm run dev
```

Electron 45는 실행 바이너리를 별도로 설치할 수 있어 설치 명령을 명시합니다. 초기 의존성/바이너리 설치에는 인터넷이 필요하지만 빌드한 앱의 사진 편집·저장에는 필요하지 않습니다.

업데이트 후 `npm ci`를 다시 실행했다면 `npx --no-install install-electron --no`도 실행한 뒤 `npm run dev`를 실행하세요. `npm ci`가 기존 node_modules를 교체하므로 Electron 실행 바이너리를 다시 준비해야 합니다. 빌드 후 `Error: Electron uninstall`로 실행이 멈추면 이 설치 명령을 먼저 실행하세요. 의존성 변경이 없는 업데이트에서는 `git pull` 후 `npm run dev`만 실행하면 됩니다.

사용 순서: **스티커 관리에서 PNG 등록 → 탐색기에서 사진(또는 폴더)을 창에 끌어 놓기 → 하단 사진 썸네일 선택 → 라이브러리 스티커 배치 → (필요하면 `저장 설정`에서 출력 폴더·형식·블로그 크기 리사이즈 지정) → 저장하고 다음**. `사진 열기`·`폴더 열기`로 추가할 수도 있습니다. 끌어 놓기와 열기는 기존 목록에 추가하며, 썸네일의 `×`로 목록에서 뺄 수 있습니다(원본 파일 유지). 폴더는 바로 아래 JPG/JPEG/PNG를 이름순으로 가져오며 하위 폴더·symlink는 제외합니다. 손상 파일은 제외 개수와 이름을 안내하고 나머지를 가져옵니다. 폴더에 후보 이미지가 100장을 초과하거나 세션 한도를 넘으면 기존 목록을 보존하고 나누어 선택하도록 안내합니다.

출력 폴더는 **세션 내 한 번 선택하면 계속 재사용**합니다. 미지정 상태에서는 첫 저장 때 선택하고 저장 성공 후 재사용합니다. 변경 선택을 취소하면 기존 폴더를 유지합니다. `<원본stem>_kkumi.png` 또는 `.jpg`로 새 파일을 만들고 충돌 시 숫자를 붙이며 원본과 기존 결과를 덮지 않습니다. 출력 폴더를 바꾸면 이미 저장한 사진도 새 폴더로 다시 저장할 수 있습니다. 앱을 다시 실행하면 출력 폴더를 다시 선택합니다.

확대/축소·100%·화면 맞춤과 `화면 이동` 드래그를 제공합니다. Ctrl/Cmd+휠로도 확대합니다. 보기 조작은 편집 이력과 저장 좌표를 바꾸지 않습니다. 사진 전환 시 미저장 수정은 저장·버리기·취소로 처리하며, 실패·취소는 현재 편집을 유지합니다. 스티커 등록·이름·분류·즐겨찾기·삭제·ZIP 백업/복원은 `스티커 관리`의 별도 modal 관리 화면에서 수행합니다.

```sh
npm run typecheck
npm run lint
npm test
npm run test:e2e
npm run build
npm start
```

실제 결과: 단위/파일 I/O 85개, Playwright Electron E2E 29개 통과(기본 스티커 1회 추가·삭제 유지, 라이브러리 2개, 빈 라이브러리 등록·스티커 끌어 놓기·선택 도구 막대, 화면 배율 1·2 픽셀 회귀, 최소 창 크기 레이아웃 회귀, 끌어 놓기·제거, 블러·모자이크·보정 저장 픽셀, ffmpeg로 회전 HEVC MOV→GIF 포함. ffmpeg가 없으면 GIF E2E는 건너뜀), 타입·lint·빌드 통과(macOS 26.3 arm64). E2E는 native 파일 대화상자의 선택 결과만 대체하고 실제 main/preload/renderer, Canvas 인코딩과 파일 저장을 사용합니다. 화면 구성은 [레이아웃 기록](./ui-layout.md), 앱 아이콘 생성(`npm run icon -- <원본.png>`)은 [아이콘 기록](./icon.md), 설치 파일 배포(`v*` 태그 → draft Release)와 자동 업데이트(공개 Release 기준)는 [배포 기록](./release.md), 최신 폴더·화면 작업 흐름은 [반복 작업 개선 기록](./workflow.md), 출력 크기·형식과 오류 검증은 [단계 D 기록](./stage-d.md), 여러 사진 편집과 검증은 [단계 C 기록](./stage-c.md), 키보드 조작은 [키보드 조작 기록](./sticker-keyboard.md), 여러 스티커 편집은 [여러 스티커 수정 기록](./multiple-stickers.md), 라이브러리 형식·제한은 [단계 B 기록](./stage-b.md)에 있으며, 이전 검증은 [단계 A 안정화](./stage-a-stabilization.md), [의존성 감사 분석](./dependency-audit.md), [Windows 검증 절차](./windows-validation.md)에 있습니다.

단계 C 이전 Windows E2E **15개 전체 통과**를 사용자 로그로 확인했습니다. **단계 C·D와 이번 반복 작업 개선의 Windows 자동·수동 검증은 대기**이며 사용자가 나중에 모아서 확인할 예정입니다. 키보드 삭제·미세 이동·입력 보호·회전 커서, 라이브러리·다중 스티커 편집과 화면 배율 1·2 회귀를 포함합니다. Windows x64 NSIS 설정과 `npm run package:win` 스크립트는 준비했지만 **패키징 및 최신 설치본의 수동 GUI 검증은 대기**입니다. 단계 A의 기본 수동 편집·저장은 이전에 사용자 성공 보고를 받았습니다. 코드 서명·업데이트·릴리스 게시를 설정하지 않았습니다.

출력 기본값은 **리사이즈 꺼짐(원본 크기)·확대 방지 켜짐·PNG·JPG 품질 100 고정**입니다. `블로그 크기로 리사이즈`를 체크하면 기본 가로 사진 1600px, 세로 사진 900px를 적용합니다. 기준은 가로 너비/긴 축을 선택하며 두 길이를 직접 바꿀 수 있습니다. EXIF 적용 후 높이가 너비보다 크면 세로 사진, 나머지는 가로 사진 기준입니다. 종횡비로 계산한 결과는 가장 가까운 정수로 반올림하고 최소 1px입니다. PNG 알파와 JPG 흰 배경 합성을 유지합니다. 설정은 재실행 유지되며 구 버전의 명시적 너비는 두 방향의 같은 길이로, 원본 크기 옵션은 리사이즈 꺼짐·1600/900 기본값으로 이관합니다. 형식·크기나 출력 폴더가 달라지면 저장 완료 표시를 구분하고 `저장하고 다음`도 새 설정으로 저장합니다.

현재 제한:

- 사진은 세션당 최대 100장, 사진별 배치는 최대 200개(블러·모자이크 영역은 별도 50개), undo/redo는 50단계입니다. 사진 썸네일은 최대 120×120이며 원본 bitmap은 현재 사진만 유지합니다(전환 중에는 이전/다음 두 장). 같은 asset의 bitmap은 공유하며 세션 전체 스티커 디코드는 모든 사진의 배치/이력/마지막 저장 복원 상태 포함 3,200만 픽셀로 제한합니다. 미저장 종료 시 저장·버리기·취소를 선택합니다. 프로젝트 자동 저장·복구는 없으며 종료 후 편집을 이어갈 수 없습니다.
- 입력 파일 최대 32 MiB, 사진 최대 1,600만 픽셀, 스티커 최대 400만 픽셀, 한 변 최대 8,192 px. 출력은 JPG/PNG 모두 1,600만 픽셀·한 변 8,192px·80 MiB 이하여야 합니다. 큰 이미지의 장시간 메모리 검증은 남아 있습니다.
- 마지막 출력 폴더·사진을 연 폴더·창 크기와 위치는 userData의 prefs.json에, 가림 기본값(모양·방식·강도)과 GIF 너비·FPS는 앱 로컬 저장소에 남겨 재실행·업데이트 후에도 유지합니다([설정 유지 기록](./persistence.md)). 저장한 폴더가 사라졌으면 첫 저장 때 다시 묻습니다. 출력 설정은 userData의 버전 있는 settings.json에 저장하며, 잘못된 입력은 저장하지 않습니다. 설정 파일 손상은 오류로 안내하고 원래 파일을 보존합니다. 프로젝트 자동 복구·색상 관리·전문 인쇄 품질을 제공하지 않습니다.
- 하드 링크 미지원 출력 폴더에서는 최종 이름을 독점 생성해 저장합니다. 실패 시 불완전한 출력을 정리하고 편집을 유지합니다. 복사 중에는 최종 파일이 잠시 보이며, 강제 종료나 OS의 삭제 거부 시 잔여 파일이 남을 수 있습니다. 삭제 거부는 파일명을 포함해 안내합니다. 실제 exFAT/FAT 장치 검증은 남아 있습니다.
- npm audit은 minimatch advisory 1개가 설치 경로 6개와 영향 패키지 25개로 전파된 상태입니다. 런타임 의존성 감사는 0건이며 현재 배포 구성에는 minimatch가 포함되지 않습니다(Windows ASAR 실제 검사는 대기). 호환되지 않는 major override/downgrade를 적용하지 않았습니다.

## 왜 만드는가

범용 사진 편집기에서 매번 PNG를 찾아 불러오거나 여러 메뉴를 오가는 번거로움을 줄입니다. 포토샵을 대체하는 전문 편집기가 아니라, **사진 선택 → 스티커 클릭 → 배치 → 저장하고 다음**에 최적화된 작은 도구를 목표로 합니다.

## 제품 원칙

1. **로컬 우선:** 사진·스티커·편집 결과를 외부 서버에 전송하지 않습니다.
2. **원본 보호:** 원본 사진과 등록에 사용한 원본 스티커를 수정하거나 덮어쓰지 않습니다.
3. **반복 작업 최소화:** 스티커 라이브러리와 출력 설정을 다시 실행해도 유지합니다.
4. **AI 없이 동작:** 사용 중 AI API·토큰·계정·구독이 필요하지 않습니다. 개발용 Codex 사용 비용과 앱 실행 비용은 별개입니다.
5. **단순한 한국어 UI:** 기능 수보다 선택·배치·저장 흐름을 우선합니다.

## 첫 버전 범위

### 사진 목록

- 로컬 폴더 또는 여러 사진 파일 불러오기.
- JPG/JPEG, PNG 지원. 그 밖의 형식은 명시적으로 지원하지 않는다고 안내.
- 미리보기, 현재 사진/전체 개수, 이전·다음 이동.
- 세션 내 사진별 편집 상태와 저장 완료/저장 후 수정 상태 표시.
- 미저장 상태로 사진을 바꾸거나 앱을 닫으면 저장·버리기·취소 선택.

### 스티커 라이브러리

- 투명 PNG 여러 개를 한 번에 등록하고 앱 관리 폴더에 복사.
- 이름 변경, 분류, 즐겨찾기, 삭제.
- 예시 분류: 고양이 / 라쿤 / 양. 특정 가족 구성이나 캐릭터에 종속되지 않는 구조.
- 원본 PNG의 위치가 바뀌어도 이미 등록한 스티커는 유지.
- 클릭해서 사진에 삽입. 위치·크기·회전 조절, 복제, 삭제, 겹침 순서 변경.
- 라이브러리 백업·복원. 사용자 이미지와 라이브러리는 Git에 넣지 않음.
- 얼굴 가림 목적의 기본 불투명도는 100%. 사진에 붙인 스티커 내부가 투명한 경우 앱이 완전 가림을 보장하지 않음.

### 편집 화면

- 하단: 가로 스크롤 사진 썸네일과 작업 상태.
- 가운데: 사진 캔버스, 화면 맞춤, 확대·축소.
- 오른쪽: 스티커 분류/즐겨찾기 필터와 배치용 미리보기, 별도 스티커 관리 화면 진입.
- 위쪽: 입력/출력 폴더, 블로그 리사이즈·형식, 저장·저장하고 다음.
- 스티커 조작에 대한 실행 취소·다시 실행.
- 확대·축소는 화면 보기만 변경하고 저장 결과의 배치를 바꾸지 않음.

### 리사이즈와 저장

- 출력 가로 너비를 지정하면 종횡비를 유지해 높이를 계산.
- 원본 크기로 저장하는 옵션, 작은 원본 확대 방지 옵션(기본 켜짐).
- 모든 사진에 공통 출력 설정 적용. 얼굴 위치는 사진마다 사용자가 조정.
- 출력: JPG(품질 100 고정) 또는 PNG. JPG로 내보낼 때 투명 영역은 흰색으로 합성.
- 출력 폴더를 선택하고 편집본을 별도 파일로 저장. 이름 충돌 시 새 이름 생성.
- `저장하고 다음`은 파일 쓰기 성공을 확인한 뒤에만 다음 사진으로 이동.
- 저장 실패·권한 부족·디스크 부족 때 현재 편집 내용을 유지하고 오류 안내.
- 마지막 사진 저장 후 완료 안내. 첫 사진으로 자동 순환하지 않음.
- 최종 이미지는 스티커와 사진을 하나로 합친 결과물. EXIF/GPS 등 원본 메타데이터는 기본적으로 전달하지 않음.

## 처음부터 넣지 않을 것

자동 얼굴 인식, 얼굴 추적, AI 이미지 생성·보정, 클라우드 동기화, 로그인, 결제, 네이버 자동 업로드, 영상/GIF 편집, 전문 레이어 효과, HEIC/RAW 지원, 자동 업데이트는 첫 버전 범위 밖입니다.

편집 프로젝트의 디스크 저장·충돌 복구·재실행 후 작업 이어하기는 후속 기능입니다. 첫 버전에서는 미저장 종료 확인과 세션 내 사진별 상태 관리를 우선합니다. 사진마다 얼굴 위치가 다르므로 단순 일괄 워터마크 기능으로 요구사항을 대체하지 않습니다.

## 기술 방향

- Electron 기반 독립 데스크톱 앱, Windows 11 x64 우선.
- React + TypeScript + Vite 기반 UI, 캔버스 편집 라이브러리 활용.
- Electron main: 파일 접근, 앱 데이터, 설정, 저장, 백업.
- renderer: 화면과 편집 상호작용. preload를 통한 제한된 IPC만 사용.
- 세부 구조, 보안, 이미지 처리 및 테스트 기준은 [AGENTS.md](../AGENTS.md)를 따릅니다.
- 개발용 macOS 실행은 보조 수단이며 Windows 검증을 대신하지 않습니다.

## 데이터와 개인정보

사진 원본은 사용자가 선택한 경로에서 읽고, 스티커는 Electron의 `app.getPath('userData')` 아래 `stickers/<UUID>.png`와 `library.json`으로 저장합니다. 라이브러리 삭제는 관리 복사본만 대상으로 하며 원본 PNG를 지우지 않습니다. ZIP 백업에는 개인 스티커와 이름/분류 메타데이터가 포함되므로 보관 위치에 주의하세요. 라이브러리는 최대 100개/PNG 총 256 MiB이며 백업·복원 제한은 단계 B 기록에 있습니다.

사진·실명·개인 경로·GPS·오류 로그의 민감정보를 원격 분석 서비스에 보내지 않습니다. 원격 콘텐츠 로딩이나 런타임 AI 연결도 기본 설계에 없습니다. 얼굴 가림은 자동 익명화 보장이 아니므로 게시 전 최종 사진을 확인해야 합니다.

## 개발 로드맵

1. Electron 안전한 기본 구조와 테스트 도구 구성.
2. 사진 한 장 + PNG 한 장 → 이동·크기 조절 → 원본 해상도 합성·저장 검증.
3. 스티커 영구 라이브러리와 백업·복원.
4. 사진 목록, 사진별 상태, 실행 취소, 저장하고 다음.
5. 출력 리사이즈·품질·오류 복구 및 개인정보 보호 검증.
6. Windows 패키징과 실제 설치/실행 검증.

## 첫 버전 완료 조건

- 재실행해도 스티커 등록과 설정이 유지된다.
- 스티커 원본을 이동해도 라이브러리를 사용할 수 있다.
- 여러 사진에 다른 위치로 스티커를 붙이고 순서대로 저장할 수 있다.
- 확대 상태와 무관하게 화면의 위치·크기·각도가 출력에 반영된다.
- 원본 파일이 바뀌지 않고, 저장 실패 시 다음 사진으로 넘어가지 않는다.
- 가로/세로 사진, EXIF 회전 사진, 한글·공백 경로, 큰 사진을 처리한다.
- 자동 테스트와 Windows 실제 앱 검증 결과를 남긴다.

## 배포 및 라이선스

최초 배포 목표는 Windows 테스트용 설치 파일입니다. 서명 없는 빌드는 Windows 보안 경고가 나타날 수 있으며, 경고 우회나 보안 기능 해제를 안내하는 대신 서명 상태를 명시합니다. 자동 업데이트와 코드 서명은 별도 결정 사항입니다.

프로젝트 라이선스와 배포 스티커의 사용 권한은 아직 정하지 않았습니다. 공개 저장소라는 이유만으로 재사용 허가를 가정하거나 임의의 오픈소스 라이선스를 추가하지 않습니다. 사용자 가족 사진·기존 캐릭터 파일은 이 저장소에 포함되어 있지 않습니다.
