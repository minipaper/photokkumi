# 반복 작업 화면 개선

요청 범위: 입력 폴더의 JPG/PNG 일괄 가져오기·하단 가로 썸네일, 출력 폴더 한 번 선택, 보기 확대/축소·이동·맞춤, 실행 취소/다시 실행/복제 단축키, 저장 시 블로그 리사이즈 체크와 가로 너비/긴 축 기준, 별도 스티커 관리 화면.

사용자 기본값: 가로 사진 1600px, 세로 사진 900px. EXIF 방향 적용 후 가로/세로를 판단한다. 두 길이를 직접 입력할 수 있고 기본 기준은 가로 너비, 확대 방지는 켜짐이다. JPG 품질 100 고정과 원본 보호를 유지한다.

구현·검증 계획: 폴더 가져오기와 방향별 출력 계산/기존 설정 이관의 실패 재현 → main의 기능 단위 폴더 API → 하단 썸네일/출력 UI/관리 dialog → Konva 보기 확대·이동과 키보드 → 실제 Electron에서 일괄 입력·출력 폴더 재사용·취소·실패·원본 불변·사진별 상태·확대 후 결과 일치·관리 분리·입력 단축키 보호를 검사한다. macOS unit/E2E/typecheck/lint/build 후 커밋·푸시하고 Windows 항목을 누적한다.

폴더는 선택한 폴더 바로 아래 파일만 대상으로 한다(하위 폴더·symlink 제외). 기존 세션 100장 상한을 유지하며 초과 시 안내한다. 관리는 별도 modal 화면으로 제공해 편집 화면과 분리하고 기존 main/preload 권한 경계를 유지한다.

## 구현 결정

- `choosePhotoFolder()`는 native 폴더 대화상자로 허용한 폴더 바로 아래의 JPG/JPEG/PNG만 이름·숫자 순서로 가져온다. `opendir`로 순회하고 후보 101개에서 중단한다. 하위 폴더·symlink·선택 폴더 밖으로 resolve되는 항목을 제외한다. 헤더·파일/픽셀 한도·실제 decode 검증은 유지한다. 잘못된 개별 파일은 제외 이름을 반환하고, 100장 상한 초과는 부분 등록 없이 기존 세션을 보존한다. 개별 파일 선택의 기존 원자성도 유지한다.
- `chooseOutputFolder()`는 main에서 사용자 선택 경로만 보관한다. renderer에 표시용 폴더명을 전달하지만 renderer가 경로를 저장 요청에 넣을 수 없다. 처음 저장할 때 폴더를 선택하는 기존 흐름도 유지하고 성공 후 세션 내 재사용한다. 변경 선택 취소는 이전 폴더를 유지한다. 저장한 사진은 마지막 출력 폴더도 기록하여 다른 폴더 선택 후 저장하고 다음을 눌러도 재출력을 생략하지 않는다. 재실행 뒤 폴더를 다시 선택한다.
- 사진 목록은 캔버스 아래 가로 스크롤 썸네일이다. 이전/다음·선택·수정/저장 완료 상태와 기존 미저장 전환 경고를 유지한다. 모든 사진을 renderer에서 미리 decode하지 않는다.
- 블로그 리사이즈 체크는 기본 꺼짐이다. 체크하면 EXIF 적용한 원본 크기로 방향을 판별해 가로1600/세로900 기본 길이를 선택한다. 가로 너비 기준은 width, 긴 축 기준은 max(width,height)를 길이에 맞춘다. 확대 방지 기본 켜짐, 최종 각 변은 반올림·최소1px이다. 두 길이와 기준을 직접 변경·재실행 유지할 수 있다. JPG 품질100·메타데이터 제거·PNG 알파·JPG 흰 배경과 출력 상한은 유지한다.
- settings schemaVersion=3으로 확장한다. v1/v2의 width=null은 리사이즈 꺼짐·1600/900, 지정 너비는 두 방향 같은 길이·가로 너비 기준으로 이관한다. 기존 형식·확대 방지를 보존하고 품질은100이다. 알 수 없는 schema나 잘못된 필드는 기존대로 거부하며 임시 파일 후 교체로 보존한다.
- `스티커 관리`는 별도 modal dialog다. 편집 화면의 라이브러리는 필터·클릭 배치에 집중하고, 등록·이름/분류·즐겨찾기 변경·삭제·백업/복원은 관리 화면에만 있다. 같은 main/preload와 앱 상태를 사용하여 별도 Electron 창/추가 sender 권한이나 복수 manifest writer를 만들지 않는다. 구 `PNG 스티커 열기` 버튼과 `chooseSticker` API를 제거했다.
- 보기 확대는1~400% 범위와 fit,100%,Ctrl/Cmd+휠을 제공한다. 확대 버튼은 사진 중심, 휠은 포인터를 기준으로 한다. 화면 이동은 Konva Stage draggable/dragBoundFunc를 사용하며 빈 바깥으로 완전히 벗어나지 않게 제한한다. Canvas 크기는 viewport로 제한해 사진 확대에 비례한 대형 화면 Canvas를 만들지 않는다. 원본 좌표·출력 Canvas와 분리하고 보기 조작은 undo에 넣지 않는다.
- Ctrl/Cmd+Z 실행 취소, Shift+Z/Y 다시 실행, D 선택 복제를 추가했다. 입력/선택 상자·contenteditable·dialog·처리 중은 기존과 같이 제외한다. 기존 Delete/Backspace·방향키도 유지한다. 사진을 바꾸면 보기는 fit으로 시작한다.

## 검증 결과

환경: macOS 26.3 arm64, 고정 Node24.22.2/Electron45.2.1. 별도 임시 프로필과 synthetic JPG/PNG만 사용했다. 의존성 변경은 없다.

폴더 API가 없는 테스트 실패와 방향별 출력 계산 실패를 확인한 뒤 구현했다. 단위 테스트는 파일 이름순·중복·손상 이미지 제외·하위 폴더/symlink 제외(macOS)·100장 초과 원자성·기존 설정 이관·리사이즈 방향/기준/상한을 검사한다. UI 회귀에서 관리 화면의 중복 노출을 정리하고, 확대 시 viewport 크기 변화 때문에 중심이 가장자리로 치우치던 동작을 보정했다.

- `npm test`: 10개 파일, 56개 테스트 통과.
- `npm run test:e2e`: 22개 전체 통과(최종28.4초). 기존20개를 새 관리/출력 UI에 맞게 수정하고 폴더·리사이즈 연속 저장 및 확대/화면 이동·단축키·관리 분리2개를 추가했다. Ctrl+휠 검사를 보완한 보기 테스트도 별도 재실행해 통과했다.
- `npm run typecheck`, `npm run lint`, `npm run build`(E2E 사전 빌드), `git diff --check`: 통과.
- 입력 폴더에서 가로/세로 사진·손상 파일·하위 폴더를 구분하고 하단 배치 위치를 검사했다. 가로1600×1018/세로900×1414 및 긴 축573×900 결과를 다시 decode했다. 출력 폴더 지정 뒤 추가 대화상자가 호출되면 실패하도록 만들어 연속 저장을 확인했고, 다른 출력 폴더로 재저장도 확인했다.
- 확대·pan 뒤 PNG 바이트가 fit 저장과 동일함을 확인했다. 키보드 undo/redo/복제, 입력/관리 화면 보호,100%/맞춤·휠,760×580 최소 창의 편집 영역 유지와 스크린샷을 확인했다. 기존 EXIF·알파·JPG100·원본 해시·저장 실패·종료·라이브러리/ZIP·화면 배율1/2 회귀도 유지한다.

Windows 자동/수동·실제 exFAT/FAT·대형 이미지 연속 메모리·설치본 검증은 대기다. 폴더 재귀 탐색·100장 초과·프로젝트 재실행 복구·출력 폴더 영구 기억은 이번 범위에 포함하지 않는다.

마지막 썸네일 검사에서 EXIF6 사진의 편집/출력은 올바르지만 nativeImage 썸네일이 원래 방향으로 남는 문제를 실패 재현했다. 최대120px로 축소한 bitmap에만 EXIF1~8 회전/반전을 적용해 해결했다. 8가지 픽셀 순서 단위 테스트와 실제 EXIF 썸네일40×60 E2E를 추가했고 원본 decode/출력에는 추가 회전을 적용하지 않는다.
