# 화면 레이아웃 정리 (2026-11-09)

## 문제
- 우측 패널(`aside`) 전체가 스크롤되는데 그 안의 스티커 그리드·배치 목록도 각자 스크롤 → 이중 스크롤.
- 상단이 제목·부제·배지 / 버튼 줄 / 출력 폴더 줄 / 출력 설정 바의 4줄(약 230px)로 캔버스 공간을 차지. 하단 안내문 2줄도 상시 노출.

## 결정
- 상단은 툴바 1줄: `포토꾸미 | 사진 열기 · 입력 폴더 선택 | 실행 취소 · 다시 실행 | 저장 설정▾ · PNG/JPG로 저장 · 저장하고 다음`.
- 출력 폴더·형식·리사이즈·확대 방지는 `저장 설정` 팝오버로 이동. 설정은 재실행 후에도 유지되므로 상시 노출하지 않고 버튼에 요약(`PNG · 원본 크기`)을 표시. 잘못된 값이면 버튼이 빨간색이 되고 저장 버튼이 비활성화됨. 바깥 클릭·Esc로 닫힘.
- 우측 패널은 스크롤하지 않는 고정 높이 열. 스티커 라이브러리 그리드만 남는 높이를 채우며 스크롤하고, 아래 `배치한 스티커`(목록·복제/삭제/순서·X/Y/너비/회전)는 항상 보임.
- 확대/축소 도구와 파일 정보(이름·크기·출력 크기·수정 상태)는 캔버스 아래 얇은 바로 이동.
- 하단은 `‹ n / N ›` + 썸네일 스트립, 그 아래 한 줄 상태바(상태·오류).
- 기능·IPC·편집 로직 변경 없음. 마크업과 CSS만 재구성. `style.css`는 누적 override를 걷어내고 토큰 기반으로 다시 작성.

## 검증 (macOS 26.3 arm64)
- `npm run typecheck`, `npm run lint`, `npm test`(56), `npm run test:e2e`(23) 통과.
- E2E는 출력 설정 조작 전 `저장 설정` 팝오버를 여는 `settings()` 헬퍼를 사용.
- 회귀 테스트 추가: 최소 창 760×580에서 페이지·우측 패널 스크롤 없음, 스티커 그리드만 스크롤, 툴바 높이 ≤ 52px, 캔버스 높이 > 250px, 선택 스티커 입력칸이 화면 안에 보임.
- Windows 화면(DPI 배율 포함) 수동 확인은 대기.

## 2차 정리 (2026-11-09, 사진 편집 흐름)
문제: 블러 영역을 선택하면 아래 패널이 커져 스티커 목록이 2줄만 남음. 복제·삭제·순서 버튼이 선택한 항목에서 멀고 `뒤로/앞으로`가 사진 이동처럼 읽힘. 좌표가 `639.64`처럼 소수점까지 보임. 첫 실행 시 스티커 등록 경로가 `스티커 관리 → PNG 등록` 두 단계.

결정:
- 선택한 스티커·가림 영역 위에 떠 있는 도구 막대(`선택 항목 도구`): 복제 · 위로 · 아래로(스티커만) · 삭제. 회전 핸들(위쪽 약 50px)과 겹치지 않게 기본은 항목 아래, 아래 공간이 없으면 회전 핸들보다 위에 표시. 드래그·변형·화면 이동·그리기 중에는 숨김.
- 오른쪽 아래 패널은 `올린 항목`(스티커+가림 목록, 가림 방식·강도)만 상시 표시. X·Y·너비·회전은 `위치·크기 숫자로 조정`으로 접어 두고, 펼침 여부는 localStorage에 기억(실패해도 접힌 상태로 동작). 숫자는 정수로 표시.
- 사진이 없으면 `올린 항목` 패널을 숨김. 빈 라이브러리에는 `스티커 PNG 추가` 버튼과 안내를 바로 표시.
- 스티커 목록 위에 PNG를 끌어 놓으면 스티커로 등록(`library:drop`). 목록 밖에 놓으면 기존처럼 사진·동영상으로 불러옴.
  - main은 경로 배열을 `validDroppedPaths`로 검증하고, lstat으로 일반 파일·`.png`만 받은 뒤 대화상자 등록과 같은 `importFiles`(디코드·크기 제한·해시 중복 확인)를 거침. symlink·폴더·다른 확장자는 `rejected`로 돌려줌.
- 편집할 때마다 상태 줄에 쓰던 `수정됨 · 저장이 필요합니다`를 없앰(캔버스 아래 정보와 중복). 상태 메시지가 없으면 단축키 안내를 흐리게 표시.
- 캔버스 아래 `화면 맞춤`·`화면 이동`은 아이콘 버튼(접근성 이름 유지). 최소 너비에서는 블러 버튼을 아이콘만이 아니라 `블러`로 표시.
- GIF 설정 패널은 출력 폴더·저장 버튼·안내를 아래쪽에 붙임.
- 사진 목록의 `‹ n/N ›`는 썸네일이 많아 스트립이 스크롤될 때 빠른 이동 수단이라 유지.

## 3차 정리 (2026-11-09)
- 툴바의 `PNG/JPG로 저장` 버튼 제거. `저장하고 다음`과의 차이는 '이동하지 않음'뿐이고 마지막 사진에서도 `저장하고 다음`이 저장 후 완료를 알려 주므로 버튼이 필요 없음. 제자리 저장은 **Ctrl/Cmd+S**(창 전체 단축키, 입력칸에서도 동작)로 유지.
- 오른쪽 탭에 `가림` 추가(세부는 `blur-regions.md`). `올린 스티커` 패널은 스티커만 표시.
- GIF 안내 문구에서 '아이폰'만 가능한 것처럼 읽히던 표현을 MOV·MP4 일반 동영상으로 수정.
- 저장 안정화: PNG 인코딩을 메인 스레드 `canvas.toBlob`에서 워커(`encode-worker.ts`, OffscreenCanvas)로 옮김. 메인 스레드 인코딩은 화면 유휴 시간에 처리돼 창이 뒤에 있으면 1~7초 이상 밀렸음(E2E에서 재현, 워커 전환 후 10~20ms). 창 `backgroundThrottling: false`로 뒤에 있어도 저장·GIF 진행이 느려지지 않게 함. 저장 실패 시 상태 줄에 `저장 중…`이 남던 문제 수정. Ctrl+S는 열린 모달(닫기·전환 확인, 스티커 관리)이 있으면 무시.
