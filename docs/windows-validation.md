# Windows 검증 기록

## 키보드 조작 추가 전 Windows 자동 테스트 보고

사용자가 Windows에서 실행한 최신 Electron E2E 로그를 제공했다. 1 worker로 14개 전체 통과, 총 16.5초다. 라이브러리 등록·재시작·원본 이동·삭제 보호, ZIP 백업/복원, 동일/다른 스티커 다중 배치·undo·합성 저장, 원본 SHA-256, 저장 실패·취소·종료, IPC·이미지 검증, EXIF 및 화면 배율 1·2 회귀를 포함한다.

아래의 자동 테스트 대기 표기는 이전 단계의 기록이다. 최신 15개 E2E 결과는 문서 하단의 키보드 조작 추가 후 확인을 기준으로 한다. 이번 보고에는 Windows/Node/npm의 정확한 버전, 단위 테스트·타입 검사·lint 결과, NSIS 빌드·설치·수동 GUI 결과가 포함되지 않았다. 해당 항목은 확인 대기로 유지한다.

## 최초 단계 A 검증 환경과 절차

현재 환경은 macOS 26.3 arm64이며 Windows 커널/VM/원격 Windows 실행 환경과 Wine/PowerShell이 없다. Windows 테스트·NSIS 빌드는 **미실행**, 실제 설치/GUI 확인은 **미검증**이다. macOS Electron 테스트 성공을 Windows 검증으로 표시하지 않는다. 이번에는 원격 저장소 업로드나 CI 실행을 하지 않았다.

## Windows 11 x64에서 실행

GUI 데스크톱에 로그인한 Windows 11 x64 장비에 Node 24.22.2와 npm, Git을 준비한다. 이 작업 폴더의 미커밋 코드를 포함한 전체 소스와 lockfile이 필요하다. 저장소의 과거 커밋만 clone하면 이번 수정이 포함되지 않는다. 개발 의존성/바이너리 다운로드에 인터넷이 필요하다.

PowerShell에서 저장소 루트로 이동해 실행한다. 설치와 테스트 오류를 다음 명령이 가리지 않도록 각 종료 코드를 검사한다.

```powershell
$ErrorActionPreference = 'Stop'
function Invoke-Checked([string] $Program, [string[]] $Arguments) {
  & $Program @Arguments
  if ($LASTEXITCODE -ne 0) { throw "$Program failed: $LASTEXITCODE" }
}
Invoke-Checked 'node.exe' @('--version')
Invoke-Checked 'npm.cmd' @('ci')
Invoke-Checked 'npx.cmd' @('--no-install', 'install-electron', '--no')
Invoke-Checked 'npm.cmd' @('run', 'typecheck')
Invoke-Checked 'npm.cmd' @('run', 'lint')
Invoke-Checked 'npm.cmd' @('test')
Invoke-Checked 'npm.cmd' @('run', 'test:e2e')
Invoke-Checked 'git.exe' @('diff', '--check')
Invoke-Checked 'npm.cmd' @('run', 'package:win')
Get-ChildItem .\release -Recurse -Filter *.exe
```

`package:win`은 production build 후 electron-builder로 Windows x64 NSIS를 만들며 `--publish never`를 사용한다. 자동 업데이트·코드 서명 자격 증명을 설정하지 않았다. 기본 예상 산출물은 `release\PhotoKkumi Setup 0.1.0.exe`이며 실제 생성된 경로를 위 목록과 빌드 로그에서 확인한다. 서명되지 않은 테스트용 빌드다. Windows 보안 설정을 낮추거나 경고 우회를 요구하지 않는다.

선택적으로 `npx --no-install asar list .\release\win-unpacked\resources\app.asar`로 목록을 확인한다(`@electron/asar`의 asar CLI는 현재 builder 전이 의존성). `node_modules/minimatch`, ESLint, electron-builder 등이 앱 ASAR에 포함되지 않았는지 확인하고 결과를 기록한다. 번들로 포함된 코드도 main/preload/renderer 소스맵 또는 빌드 설정과 함께 확인한다. 설치 파일이 생긴 것만으로 감사 범위 밖 바이너리의 보안을 보장하지 않는다.

## 사람이 확인할 체크리스트

- [ ] 설치 → 실행 → 한글·공백·긴 경로의 JPG/PNG 사진과 투명 PNG 스티커 열기. 인터넷을 끊어도 편집/저장 가능.
- [ ] 이동·모서리 비율 유지 크기·회전 → PNG 저장. 원본 크기, 알파, 배치/잘림 확인. DPI 100%와 150%에서 조작 확인.
- [ ] NTFS 폴더와 하드 링크 없는 exFAT/FAT 출력 장치에 각각 저장. 같은 이름으로 반복 저장해 숫자 suffix와 기존 결과 보존 확인. 가능하면 앱 두 프로세스에서 같은 사진/폴더에 동시 저장.
- [ ] 권한 없는 폴더·저장 대화상자 취소 → 사진/스티커/각도 유지, 다른 폴더로 재시도. 작업이 끝난 뒤 실패한 PNG/`.tmp`가 남지 않았는지 확인. OS가 삭제를 거부하면 앱의 정리 실패 안내를 확인하고 파일 상태를 기록.
- [ ] 수정 후 X/Alt+F4와 앱 종료 요청: 저장·버리기·취소 각각 확인. 저장 실패·폴더 선택 취소는 종료 취소. 저장 성공만 닫힘. 작업 중 반복 닫기도 확인.
- [ ] 저장 전후 원본 사진·스티커 `Get-FileHash -Algorithm SHA256` 일치 확인. 기존 출력 해시 보존 확인.
- [ ] 재실행하면 새 한 장 세션으로 시작함을 확인하고, 앱 제거 흐름 확인. 원본/내보낸 파일이 삭제되지 않아야 함.

## 결과 기록 양식

Windows 버전/아키텍처, DPI, Node/npm/Electron 버전, 실행 명령, 통과/실패 수, 설치 파일 실제 경로·SHA-256·서명 상태를 기록한다.

- 자동 테스트: 대기
- Windows x64 NSIS 패키징: 대기
- ASAR 의존성 포함 목록: 대기
- 설치/GUI/오프라인/제거: 대기
- NTFS 및 실제 exFAT/FAT/경합/권한/긴 경로: 대기

패키징 성공과 사람이 설치한 앱을 검증한 결과를 각각 적는다. 실패 시 단계 A 문제만 수정하고 라이브러리·다중 사진 기능으로 범위를 넓히지 않는다.

## 단계 B 추가 확인

단계 A의 Windows E2E 11개와 기본 수동 편집/저장은 사용자 성공 보고를 받았다. 다음은 이번 단계 B 수정 이후 다시 확인해야 한다. `npm ci`로 추가 ZIP 의존성을 설치한 뒤 기존 명령을 수행한다. E2E는 현재 13개다.

- [ ] 여러 PNG 등록 → 이름/분류/즐겨찾기 변경 → 원본 PNG 이동 → 앱 완전 종료/재실행 → 유지 및 썸네일 확인.
- [ ] 라이브러리 클릭 배치·PNG 저장, 현재 사용 중 삭제 차단, 다른 항목 삭제 시 원본 보존.
- [ ] ZIP 백업 → 다른 테스트 프로필에서 복원 → 재복원 중복 없음. 취소/잘못된 ZIP은 기존 항목 유지.
- [ ] 설치본의 실제 userData 경로와 업그레이드 후 라이브러리 유지, 권한 거부 폴더에서 오류 안내 확인.

단계 B를 포함한 최신 Windows E2E 14개는 사용자 보고로 통과했다. NSIS 빌드·실제 설치/수동 GUI 결과는 대기다.

## 한 사진 여러 스티커 수정 후 확인

현재 `npm run test:e2e`의 예상 결과는 14개다. 이번 변경은 의존성 추가가 없어 이미 단계 B 의존성을 설치했다면 `npm ci`를 반복할 필요는 없다.

- [ ] 같은 라이브러리 스티커를 3번 클릭하고, 다른 스티커도 추가해 기존 배치가 사라지지 않는지 확인.
- [ ] 사진에서 클릭하거나 배치 목록으로 각각 선택 → 이동·크기·회전. 복제·선택 삭제·앞/뒤 순서와 실행 취소/다시 실행 확인.
- [ ] 겹친 결과를 PNG로 저장해 모든 배치와 순서가 보이는지 확인. 저장 실패·종료 취소 시 전체 배치 유지 확인.
- [ ] 선택하지 않은 배치나 실행취소 이력에서 쓰는 라이브러리 항목도 삭제되지 않는지 확인. 배치·이력 비우기의 취소/확인 후 참조 해제 확인.

Windows E2E 14개 전체 통과(16.5초)는 사용자 로그로 확인했다. 위 체크리스트의 실제 설치본 수동 결과는 대기다.

## 키보드 조작 추가 후 확인

키보드 조작 변경 후 Windows에서 1 worker로 E2E 15개 전체 통과한 사용자 로그를 확인했다. 신규 키보드 이동·삭제·입력 보호·회전 커서와 기존 회귀 테스트 모두 통과했다. 총 실행 시간은 제공되지 않았다. 아래 항목은 설치본의 수동 확인용이며 자동 테스트 성공과 구분한다.

- [ ] 스티커를 마우스로 선택 → 방향키 1px·Shift+방향키 10px 이동 → 실행 취소/다시 실행 및 저장 위치 확인.
- [ ] Delete/Backspace로 선택한 배치만 삭제. 키를 길게 눌러도 다른 배치까지 연속 삭제되지 않는지 확인.
- [ ] 이름/분류·숫자 입력 중에는 키보드 입력이 스티커 삭제나 이동을 일으키지 않음. 종료 확인창에서도 조작 차단.
- [ ] 회전 핸들 hover 시 원형 화살표 커서, 이탈 시 기본 커서 확인(DPI 100%/150%).

## 단계 C 누적 확인 (Windows 대기)

사용자 요청에 따라 macOS에서 구현·자동 검증 후 반영하고 Windows는 추후 일괄 확인한다. 단계 C 이전 E2E 15개 통과와 구분한다. 업데이트 뒤 의존성 변경이 없으면 `git pull` → `npm run test:e2e` → `npm run dev`. `npm ci`를 실행했다면 개발 실행 전에 `npx --no-install install-electron --no`도 실행한다. 단계 C E2E 예상 결과는 17개다.

- [ ] 가로/세로·한글/공백 경로 사진 여러 장을 선택. 목록·썸네일·번호와 사진 추가·중복 제외 확인.
- [ ] 사진마다 다른 스티커 위치·크기·회전 → 저장하고 다음. 이전 사진 복귀 시 배치·선택·undo/redo가 독립적으로 유지됨.
- [ ] 수정 후 사진 전환에서 저장·버리기·취소. 버리기는 마지막 저장 배치로 복원(미저장은 빈 배치). 취소·저장 취소/실패·대상 사진 누락 시 현재 사진 유지.
- [ ] 저장 완료 → 수정하면 저장 후 수정 표시. 마지막 사진 저장 후 완료 안내, 다시 눌러도 재저장/첫 사진 순환 없음.
- [ ] 현재 사진 밖의 배치/이력/저장 복원 상태에서 참조하는 스티커 삭제 차단. 사진 변경 뒤 Delete·Backspace·방향키와 입력 중 보호 확인.
- [ ] 연속 저장 중 중복 클릭·사진 전환 차단, 종료 확인과 저장 실패 복구, 원본 SHA-256 불변.
- [ ] DPI 100%/150%, 최소 창 크기에서 목록/캔버스/라이브러리 사용성, 대량 사진 전환 중 메모리 확인.

단계 C Windows E2E·수동·NSIS/설치 결과: 대기.

## 단계 D 누적 확인 (Windows 대기)

최신 E2E 예상 결과는 **20개**다. C의 17개 안내보다 이 숫자를 우선한다. 의존성 변경은 없다. `git pull` 후 `npm run test:e2e`, `npm run dev`로 확인한다. `npm ci`를 했다면 `npx --no-install install-electron --no`를 먼저 실행한다.

- [ ] 가로/세로·EXIF 회전 JPG·투명 PNG에 회전/겹침/사진 밖 스티커를 배치. 원본/너비 지정으로 PNG와 JPG를 저장하고 크기·위치·잘림·방향 확인.
- [ ] 확대 방지 켜짐/꺼짐·정수 너비·극단적 세로 비율·픽셀 상한 안내 확인. PNG 품질 비활성화, JPG 품질 100 고정과 기존 90/낮은 품질 설정의 100 전환 확인.
- [ ] 투명 사진·반투명 스티커는 PNG에서 알파 유지, JPG에서 흰 배경 합성. 원본/기존 파일 보존과 한글·긴 경로·같은 이름 충돌 suffix 확인.
- [ ] 저장한 사진의 출력 크기/형식 변경 → 출력 설정 변경 표시 → 저장하고 다음이 재저장. 마지막 사진 반복 버튼은 설정이 같으면 추가 출력 없음.
- [ ] 재실행 후 형식/너비/확대 방지/품질 유지. 설정 파일 쓰기 실패 시 이전 파일·편집 유지, 이미지 저장과 다음 이동 차단, 버리기 종료 가능 확인.
- [ ] 출력 폴더 취소·권한 거부·디스크 부족 시 현재 사진/배치 유지와 재시도. NTFS/exFAT/FAT에서 임시/불완전 출력 정리, 원본 SHA-256 확인.
- [ ] 한도 근처 큰 사진 연속 리사이즈 중 메모리, DPI 100%/150%와 최소 창 크기에서 출력 설정·목록·캔버스 사용성 확인.

단계 D Windows E2E·수동·NSIS/설치 결과: 대기. macOS 검증과 구분한다.

## 반복 작업 화면 누적 확인 (Windows 대기)

최신 E2E 예상 결과는 **22개**다. 가로1600/세로900 기본값과 리사이즈/스티커 관리 화면에 맞춰 이전 단계의 버튼 안내보다 아래 절차를 우선한다. 의존성 변경 없이 `git pull` → `npm run test:e2e` → `npm run dev`로 확인한다. `npm ci`를 했다면 `npx --no-install install-electron --no`를 먼저 실행한다.

- [ ] 입력 폴더 바로 아래 JPG/JPEG/PNG 가져오기, 하단 썸네일 가로 스크롤·선택·이전/다음·작업 상태. 하위 폴더/symlink 제외·손상 파일 안내·100장 초과 시 기존 목록 보존.
- [ ] 출력 폴더 한 번 지정 → 여러 사진 저장하고 다음에서 추가 폴더 선택 없음. 변경 취소는 기존 폴더 유지, 다른 폴더로 변경 시 같은 사진도 재저장. 재실행하면 폴더 다시 선택.
