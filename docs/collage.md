# 사진 합치기 (2026-11-28)

블로그용으로 사진 2~10장을 한 장으로 합치는 다섯 번째 작업 모드. 툴바 탭 `사진 합치기`(좁은 창 `합치기`, aria-label 고정). 썸네일·스티커 만들기처럼 별도 화면이며, 사진은 사진 편집 탭에서 연 목록(하단 썸네일)에서 고른다.

## 결정
- **편집한 사진을 쓴다.** 저장 경로(`composePng`)를 `composeBitmap`(비트맵 반환) + PNG 인코딩으로 나눠, 합치기도 저장과 같은 함수로 사진마다 90° 회전·기울기 → 보정 → 블러·모자이크 → 스티커 → 글자 → 자르기를 원본 해상도로 그린다. 리사이즈(저장 설정)는 적용하지 않는다(합치기 너비가 따로 정한다). 사진 편집에서 고치고 돌아오면 그 사진의 미리보기만 다시 그린다(사진별 현재 장면 객체가 바뀌었는지로 판단). 합치기 탭으로 갈 때 편집 중인 자르기 상자는 실행 취소 한 단계로 확정한다.
- **레이아웃 6종** (`src/shared/collage.ts`): 2장 가로(3:4 칸 둘), 2장 세로(4:3 칸 둘), 3장 큰 1+작은 2(위 큰 칸, 아래 작은 칸 둘, 모두 3:2), 3장 가로(3:4 칸 셋), 4장 2×2(정사각형), 세로 이어붙이기(2~10장, 사진마다 비율 유지, 너비 = 출력 너비 − 바깥 여백). 격자 칸은 비율을 지키므로 간격이 있으면 전체 높이가 그만큼 늘어난다. 칸 경계는 정수 픽셀(행 안에서 칸 너비 차이 최대 1px).
- **칸**: 사진이 칸을 꽉 채운다(cover). 칸 안을 끌면 사진이 포인터를 따라 움직이고 가장자리를 넘지 않는다. 휠·`확대` 슬라이더(100~400%, cover 기준)·`+`/`-` 키로 확대, 방향키 10px(Shift 50px) 이동. 칸을 누르고 아래 사진을 누르면 그 칸에 들어가고, 칸을 고르지 않았으면 첫 빈 칸(이어붙이기는 끝에 추가). `⇄ 다른 칸과 바꾸기` 뒤 다른 칸을 누르면 사진과 위치·확대가 함께 바뀐다. `빼기`는 칸을 비우고, 이어붙이기에서는 3장 이상일 때 칸 자체를 없앤다.
- **레이아웃을 바꾸면** 놓인 사진은 자리를 지키고(넘치는 칸은 끝에서 빠짐), 빈 칸은 아직 안 쓴 사진으로 목록 순서대로 채운다. 처음 여는 이어붙이기는 사진을 최대 10장까지 모두 넣는다. 목록에서 빠진 사진은 칸에서도 빠진다.
- **설정**: 간격 0~40px(출력 기준), 바깥 여백 켜기(간격과 같은 두께), 배경색 6가지(흰색·검정·연한 회색·베이지·연분홍·하늘)+직접 고르기, 모서리 둥글게 0~40px(칸마다), 너비 1080·1600·2000px, JPG·PNG. 기본값 2×2·1080·간격 10·여백 켬·흰색·모서리 0·JPG. 설정은 `pk.collage`(앱 로컬 저장소)에 남고 칸 배정은 앱을 켜 둔 동안만 유지한다. 합치기에는 "저장 안 한 편집" 확인이 없다(스티커 만들기와 같음).
- **저장**: renderer가 출력 크기 OffscreenCanvas에 배경을 칠하고, 칸마다 편집한 사진을 원본 해상도로 하나씩 그려 넣은 뒤 바로 해제한다(큰 사진은 한 번에 한 장만 메모리에). 화면 미리보기를 캡처하지 않는다. 미리보기는 같은 배치 계산·그리기 함수(`drawCell`)로 긴 변 1,200px 사본을 그린다. PNG 바이트를 `collage:save` IPC로 보내면 main이 모양(키 5개, 사진 ID 36자, 형식, 정수 크기)·사진 ID가 연 목록에 있는지·바이트 상한 80 MiB·PNG 서명·1,600만 픽셀·한 변 8,192px(`inspectImage`)·헤더와 디코드 크기가 요청과 같은지·JPG면 모든 픽셀 불투명인지 확인하고 픽셀을 새로 인코딩한다(JPG 품질 90, 메타데이터 없음). 이름은 첫 칸 사진의 `<stem>_collage.jpg|png`, 이미 있으면 `_1`, `_2`…(`saveUnique`, 원본·기존 파일을 덮지 않음). 출력 폴더가 없으면 처음 저장할 때 고른다.
- **한도**: 앱의 다른 저장과 같은 1,600만 픽셀·한 변 8,192px. 격자 레이아웃은 2000px에서도 한도 안이다(가장 큰 2장 세로가 2000×3000). 세로 이어붙이기가 한도를 넘으면 너비·간격·모서리를 같은 비율로 줄여 맞추고 크기 옆에 `(한도에 맞춰 줄임)`을 보여 준다. 예: 1080 너비·간격 10·여백 켬에 세로 사진(3:4) 10장은 높이 14,240px → 약 621×8,186으로 줄어든다. 너비가 200px 밑으로 내려가야 하면 저장하지 않고 사진 수를 줄이라고 안내한다.
- 탭이 다섯 개가 되어 960px 이하에서는 `사진·썸네일·합치기·스티커·영상`으로 줄인다. 미리보기 사진을 준비하거나 저장하는 동안 다른 탭과 끌어 놓기를 막는다(사진 읽기는 main의 작업 잠금을 같이 쓴다). 합치기 탭에서 사진을 끌어 놓으면 목록에 더해지고 합치기 화면에 머문다.

## 검증 (macOS 26.3 arm64)
- `npm run typecheck`, `npm run lint` 통과. `npm test` 29개 파일 176개 통과(새 `tests/collage.test.ts` 12개: 레이아웃 6종·칸 수, 2×2 간격·여백 정수 좌표, 모든 격자·너비·간격에서 겹침 없음·비율·여백, 이어붙이기 비율·높이·장수 제한, 한도 축소(높이·픽셀 한도, 간격·모서리 비례, 불가능한 경우 거부), cover·끌기·확대 범위, 레이아웃 전환 시 배정 유지·채우기, 사진 누르기·바꾸기·빼기, 설정·저장 요청 검증).
- `npm run test:e2e` 42개 통과(1.3분, 새 `tests/e2e/collage.spec.ts` 1개): 합성 단색 PNG 4장(첫 장 왼쪽에 자홍 띠) 열기 → 2번 사진을 사진 편집에서 90° 회전 → 합치기 2×2·간격 20·검정·PNG, 1번 칸을 오른쪽 끝까지 끌기 → 저장한 PNG를 다시 디코드해 1080×1080, 칸 가운데 색 4개, 끌어서 드러난 자홍 띠, 간격·바깥 여백 검정 확인 → 다시 저장하면 `_collage_1.png` → 1·4번 칸 바꾸기 → 세로 이어붙이기·간격 10·여백 끔·흰색·JPG에서 1080×3360(회전한 2번 사진이 3:2로 들어감) 크기·칸 색·흰 간격 확인 → 위조 요청(없는 사진 ID·경로 문자열·추가 키·크기 불일치) 거부 → 760×580에서 페이지·패널 스크롤 없음, 탭 글자 잘림 없음, 툴바 한 줄(사진 편집·썸네일 탭 포함), 패널 마지막 줄 아래 여유 59px, 저장 버튼 화면 안 → 원본 4장 SHA-256 불변. 실행 후 `pgrep -fl "out/main/index.js"` 남은 프로세스 없음.
- 기존 E2E의 preload API 키 목록에 `saveCollage`를 더했다.
- README 스크린샷 `docs/images/collage.png`: `npm run build && npm run shots`(합성 그림, 임시 출력 폴더 경로는 이름만 보이게 바꿈). 다른 스크린샷 파일은 이번 변경과 무관해 다시 만든 결과를 넣지 않았다.

## 미검증·남은 것
- Windows 실제 화면(맑은 고딕 너비·높이에서 760×580 패널 여유, DPI 배율), 큰 사진 10장 이어붙이기의 속도·메모리.
- 칸 배정·확대 위치는 앱을 끄면 사라진다(프로젝트 저장 없음).
